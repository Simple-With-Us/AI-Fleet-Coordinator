# Bounded Named Infisical Reads

`fleet_infisical.bounded_fetch_project` runs one logical named-read operation in a disposable process using the same canonical client.  The child performs the existing grant metadata checks, bounded concurrent named GETs, record provenance validation and decoding.  Its existing `named-fetch` protocol is unchanged; no mutation, arbitrary callable or source dispatch is available.

Consumers replacing `fetch_verified` pass `strict_records=True`.  That option reaches the shared verifier inside the child and requires explicit matching workspace, prod environment and folder, a shared row, `secretValueHidden` exactly false and a nonempty string value for every requested key.  The ordinary single-scope reader contract remains available for existing consumers; an exact token grant alone does not supply the additional row proof required by a verified credential read.

The parent starts a monotonic budget before launch, reserves the smaller of 100 ms or one fifth of the remaining budget for cleanup, and caps both private pipe directions independently.  Requests are limited to 128 KiB; the serialized whole-batch result defaults to 1 MiB and callers can select a narrower cap.  The parent accepts only a complete version-one result from an exited child before expiry.  Partial, malformed, excessive or late output fails closed and cannot update the caller's cache.

Only the explicit consumer binding and selected provider/prod/path metadata enter private stdin.  The token is absent from argv, inherited environment, files and diagnostics.  The child uses the current absolute Python in isolated mode and the same reviewed module, with a minimal environment and discarded stderr.  Provider text and arbitrary exception strings are excluded from errors.

An unresolved reference retains the fixed `unresolved-reference` diagnostic and exit code 5 across the worker boundary.  The private refusal contains no secret name, value or provider text; the parent accepts that classification only with its exact typed code and matching child exit.

On timeout or interruption the parent kills only its owned child and performs bounded cleanup.  Cleanup failure has a distinct fixed unavailable diagnostic; an interrupted call preserves KeyboardInterrupt or SystemExit and chains that fixed failure as its cause rather than hiding it.  A final deadline check after local key/value/reference validation prevents late success.  Validation is byte/node bounded and cannot itself be interrupted at an exact instant.  Provider, resolver and executor waits are bounded after normal process launch; the API does not promise an unconditional return within exactly three seconds under an uninterruptible OS launch or scheduling stall.

The existing `fetch_project` and lower-level HTTP operations retain their socket-budget semantics.  The writer's sent/unsent callbacks, retained ledger, acknowledgments, unknown outcomes and reconciliation are unchanged.  A timed-out read worker never establishes that a mutation was unsent.  The coordinated letter-bootstrap source calls this generic operation with a three-second budget and an 8 KiB serialized answer cap; the library itself installs nothing and activates no consumer or credential.

## Explicit File Operation

The same private worker also accepts the disjoint `file-named-fetch` operation.  Its exact fields are `schema`, `operation`, `project_slug`, `path`, `env`, `token_file`, `names`, `timeout` and `max_output_bytes`.  It accepts no raw token, writer option, strictness option or executable/source selector.  Unknown fields refuse before file or provider access.

This operation alone requires a finite future token expiry, exact read-only project/prod/folder scope and strict credential rows.  The additive `require_finite_expiry=False` keyword on the direct metadata/verification/fetch helpers preserves existing callers, including their explicit-null read-only expiry compatibility.  The file operation hardcodes true; the caller cannot relax it.

Only Python reads the explicitly selected absolute raw-token file.  The descriptor walk permits protected root/current-user directories and only the actual root-owned sticky `/tmp` or `/private/tmp` shared anchors.  It rejects retired `.secrets` paths and aliases, leaf symlinks, nonregular objects, foreign ownership, extra links, modes other than 0400/0600, oversized content and changed file/name/directory identities.  The token is limited to 8 KiB; assignments and shell syntax are not alternate formats.  Closed `bootstrap-file-refused` replies retain no path or OS error.

Project metadata stays inside this child.  Explicit configured IDs precede the existing home-project file and malformed explicit IDs never fall back.  The local file-operation resolver preserves the current stripped-first-line format while limiting the nonsecret file to 4 KiB and checking its regular type, no-follow descriptor, ownership and write permissions.  It introduces no new metadata source and does not change `infisical_project_id`.  Its closed refusal is `project-binding-required`.

`simple_tools/registry_export_reader.mjs` is the shared credential seam for both registry exporters.  An explicitly supplied `GOOGLE_SHEETS_SA` retains precedence.  Otherwise the adapter requires its own explicit `OPERATOR_SHEETS_TOKEN_FILE` and home, with optional existing Fleet-OPS project-ID metadata.  It fixes Fleet-OPS prod `/google-sheets-sa` and requests only `GOOGLE_SHEETS_SA`; it forwards no ambient auth, Python environment or provider override.  The installer's selector name does not establish shared custody or permission to use its store.

The Node parent starts exactly one isolated Python child, reserves one second of its thirty-second budget for cleanup, bounds private input to 128 KiB and complete output to 64 KiB, and accepts only the exact successful reply from an exited child.  Timeout, abort, excessive output, malformed replies and exit mismatch refuse without retry; kill/closure handling remains bounded and an OS cleanup failure is reported as unavailable.  Python calls direct `fetch_project`, so this route starts no grandchild.  OS launch, scheduling and uninterruptible filesystem limits still apply.

The adapter and canonical Python file form the credential-reader payload.  Importing both current exporters additionally requires the thread exporter's existing `operator_sheets_google.mjs` scanner dependency; manual writes retain the existing dynamic drain/lease dependency.  Release membership of the session exporter and the scheduled drain's own SA-file transport are unchanged.  Tests use synthetic protected files, copied code and loopback providers; no installed store, grant, deployment or live Sheets acceptance is established by source tests.
