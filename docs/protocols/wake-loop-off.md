# Temporary wake-loop prevention switch

`daemon.wake_loop_prevention` is a typed boolean, default true. False disables only the topic wake-loop guard. Capture, coalescing, budgets, stale handling, identity checks, duplicate suppression and all other wake controls still apply. Counters remain recorded; nothing resets them or replays old drops. Status exposes `wake_loop_prevention` separately from the active `loop_guard` list. Reload applies the switch to the existing guard. Re-enabling is a separate owner decision, never automatic.

The authoritative non-secret setting is `AGENT_SYNC_WAKE_LOOP_PREVENTION` in the listener's Infisical project, production `/zulip`. The setup-only `scripts/agent_sync/server/project_loop_prevention.py` consumes a freshly retrieved raw-secret object on stdin, validates its project, environment, folder, name and exact boolean, then projects only this setting into the existing listener TOML volume. It does not fetch credentials, signal the daemon, clear counters or start wakes. Dry-run is the default; `--apply` atomically writes after validating unrelated parsed configuration is unchanged.

The projection is a derived offline-required runtime copy, not a second authoritative setting. It is necessary because this listener consumes machine-specific TOML and has no live service-token knob reader yet. Keeping the projection through an Infisical outage or restart avoids silently re-enabling the guard. Do not edit this setting directly in TOML. Change Infisical under owner authority, verify the current value, project it and reload. A service-token reader can replace this narrow setup projection later without broadening runtime machine-identity access now.
