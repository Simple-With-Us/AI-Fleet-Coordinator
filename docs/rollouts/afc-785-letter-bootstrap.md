# Shared Letter Client Bootstrap

An interactive letter client needs its own scoped Infisical service token to fetch the registry address and signing key.  The shared `platform-letter` and `simple-chat letter` entry points bind that token once per process, independent of seat and platform adapter.  The signing key remains an Infisical value held in memory.

Private token-file custody is implemented once in `fleet_infisical_bootstrap.bind_private_token`, with an explicit consumer directory, filename and binding name.  The letter wrapper declares its own store; other consumers must declare and provision their own stores rather than borrowing this one.  The shared helper never discovers credentials or creates a store.

This is the interactive launcher slice of AFC-785.  [PR #2167](https://github.com/Simple-With-Us/AI-Fleet-Coordinator/pull/2167) supplies the shared direct Infisical library and knob-reader migration; [PR #2168](https://github.com/Simple-With-Us/AI-Fleet-Coordinator/pull/2168) migrates the native Zulip, Notes and FleetLink readers.  [PR #1838](https://github.com/Simple-With-Us/AI-Fleet-Coordinator/pull/1838) owns the single letter client and its platform table.  Service registrars keep their own registered bootstrap bindings.  The broader issue stays open until all remaining runtime consumers and deployments are verified.

The host's consumer store is `~/.config/platform-letter/infisical-registry.token`: an owner-only regular file with mode `0600` in a directory with mode `0700`.  Surrounding ASCII whitespace, including a final newline, is accepted.  The bootstrap reader refuses symlinks, hard links, public files or directories, non-regular files, malformed values and oversized values.  It never changes an explicit `SIMPLE_TOOLS_OPERATOR_REGISTRY_INFISICAL_TOKEN` binding and never reads another consumer's token, an old registry helper or a signing-key cache.  An unavailable binding produces a diagnostic naming that variable and disables registry access; chat startup continues.

Provision the shared host consumer a read-only service token for AI Fleet Coordinator, `prod`, exact folder `/operator-registry`, with an expiry.  That folder contains only `SIMPLE_TOOLS_OPERATOR_REGISTRY_URL` and `SIMPLE_TOOLS_OPERATOR_REGISTRY_KEY`; the client requests those two names through the shared direct Infisical library with one three-second deadline and an in-memory process cache.  It does not use the wake-router folder or the generic knob token.  Verify the token's own metadata, intended named reads and an unavailable outside-folder value before use.  Record its metadata in the Infisical Service Tokens registry and the Fleet-OPS mirror.  Keep the value solely in the protected consumer store; never pass it in arguments or messages.

The coordinated source includes the retained shared-client follow-up [PR #2188](https://github.com/Simple-With-Us/AI-Fleet-Coordinator/pull/2188) and bounded named-read [PR #2198](https://github.com/Simple-With-Us/AI-Fleet-Coordinator/pull/2198).  Registry reads use that generic whole-operation worker with a three-second budget and an 8 KiB serialized answer cap, rather than relying on a socket inactivity timeout.  The client refuses a foreign preloaded reader origin before passing its binding.  Only complete, validated worker results can enter the process cache; timeout/failure retains the existing short failure cooldown and never switches to another consumer.  The [shared deadline contract](../protocols/bounded-infisical-reads.md) states the OS scheduling and local validation limits.  Source adoption is separate from installing a host wrapper or verifying native delivery.

During migration, preserve the existing registry values and grants used by other consumers.  A synchronized unchanged-value copy in the narrower folder bridges this rollout; migrate the remaining registry consumers before retiring the old values.  Install the narrower host grant only after this source and its shared-library dependency are available for acceptance, then prove an assignment or touch in the intended session before revoking its superseded grant.

A refused file leaves an empty binding marker in the process environment so registry reads fail closed instead of consulting another consumer's generic token.  Presence alone does not mean that a token was bound; the safe bootstrap reason and registry diagnostic distinguish that failure.

Deploy the reviewed source through the normal fleet CLI release path.  Run the shared letter request in the intended interactive session and verify the registry's assignment and persisted title.  A loader test or a successful health check alone does not prove assignment.

The managed `platform-letter` wrapper uses the ordinary isolated Python launch and no longer sources either legacy registry-env helper.  Its routine managed-wrapper refresh removes the old sourcing path.  Before activating the new source on any host, verify that host's own narrow consumer bootstrap is installed and usable; preserve a working host wrapper until its replacement route passes.  The server acceptance alone does not establish Mac readiness.

Rollback the source through the fleet CLI release path if needed.  Preserve the consumer token until the replacement path is live and verified; remove obsolete helpers and signing-key caches only after auditing their remaining callers.
