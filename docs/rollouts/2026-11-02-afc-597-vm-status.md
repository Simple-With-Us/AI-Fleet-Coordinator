# VM status collector (AFC-597 slice S4, collector half)

## Summary

This change adds the per-VM half of the fleet status story.  A new stdlib-only collector writes, or prints, one private JSON report per VM.  Nothing is installed on any VM by this change.  The owner installs per VM later, and the pull transport is a forced-command SSH key per VM as documented in the protocol note.

## Why

Muster already reads the server report and treats a report older than 45 minutes as unknown.  The seats that live on VMs had no equivalent, so their load, disks, processes, harness sessions and dirty checkouts were invisible.  The collector closes that gap in the same shape and with the same discipline as the server collector.

## Files

- `scripts/fleet-vm-status.py` is the collector.  The default run writes `~/.local/state/fleet-tools/vm-status.json` with mode 0600 atomically.  `--json` prints the report and writes nothing, for the forced-command pull.
- `scripts/test_fleet_vm_status.py` carries the tests.  They were written first and run red against the missing collector, then green.
- `scripts/systemd/fleet-vm-status.service` and `scripts/systemd/fleet-vm-status.timer` mirror the server units: a user oneshot every 15 minutes, persistent, with `Nice=10` and linger required.
- `docs/protocols/fleet-vm-status.md` documents the report, the per-VM install, the forced-command `authorized_keys` line, and revoke by deleting that line.

## Report shape

The document carries `schemaVersion`, `tool`, `generatedAt`, `hostLabel`, `seats`, `uptimeSec`, `load1`, `load5`, `load15`, `cpuCount`, `memory`, `swap`, `disks`, `processes`, `harnessSessions` and `checkouts`.  A measurement that cannot be taken is omitted and never reported as a zero.  Processes are allowlisted executable basenames only, identified by `/proc` exe and comm, never by argv or environment.  Harness session files are counted by `stat`, never opened.  Checkouts are read with local git plumbing only, with no network.

## Verification

Commands actually run in this lane:

- `python3 scripts/test_fleet_vm_status.py` before the collector existed: red with `FileNotFoundError` for `scripts/fleet-vm-status.py`.
- `python3 scripts/test_fleet_vm_status.py -v` after the collector: 17 tests, OK.  They cover omit-never-zero on host numbers and disks, allowlisted process names only (a non-allowlisted exe never appears) with count and oldest start, host label and seats parsing (a raw IP is refused as a label), harness session counts with no content in the output, dirty counts and unpushed on a temp git repo, the `--json` shape with nothing written, and the atomic 0600 write.
- `python3 scripts/test_fleet_server_status.py` (the neighboring suite): 64 tests, OK.
- A `--json` smoke run against a temp home on the Mac printed the document with the label, seats, load, cpu count, both disks and an empty checkout list.  The `/proc`-only sections (processes, uptime, memory and swap) were omitted on the Mac, which is the omit rule working as designed.  No report file was written.
- `ruff` is not installed in this lane's interpreter (`No module named ruff`), so no lint claim is made.

## Unresolved

- No VM is installed yet.  Each VM still needs the owner's install pass from the protocol note, including linger and the forced-command key.
- The Muster-side reader for `vm-status.json` is sibling work under AFC-597 and is not in this change.
- On the forced-command pull, `seats` is omitted unless the VM's sshd permits an `environment=` option, as noted in the protocol doc.
