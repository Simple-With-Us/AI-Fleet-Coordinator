# [AFC-740](https://linear.app/simple-with-us/issue/AFC-740) One Letter Client:  Steps At Merge

One client, `platform-letter`, letters the chats of every platform from this change on, Claude Code and MiniMax Code included.  The two per-seat clients it replaces are gone from the checkout:  `scripts/simple_tools/claude_letter.py` (behind `simple-chat letter`) and `scripts/mm_session_letter.py` (behind `mm-session-letter`).

This page is the order of work on the Mac and on the server when the change merges, the check that proves each step, what to take away afterwards, and how to go back.  None of it was run against a real home, a real `authorized_keys` or the real registry in this change:  every command below was run against a throwaway home and an in-process registry.  The server was not reached at all.

## What Needs No Step

- **Claude hooks keep working.**  The entries installed today run `simple-chat letter hook` with no `--platform`.  The new runtime reads that command line as the Claude hook, and reads the retired client's `CLAUDE_LETTER_LOCATION`, `CLAUDE_LETTER_REMOTE` and `CLAUDE_LETTER=0` as `--location`, `--mac-ssh` and off.  So no Claude chat is without its letter hook between the runtime's update and the install, on the Mac or on the server, and the Claude install below can wait for a quiet moment.
- **The registry settings reach a hook through the host's wrapper, not through this code.**  A hook is launched with no profile, so its environment holds neither `SIMPLE_TOOLS_OPERATOR_REGISTRY_URL` nor its key, and a hook that runs with neither answers `not_configured` and no chat gets a letter.  On the Mac `~/.local/bin/platform-letter` (a link to `~/.local/libexec/simple-tools-hooks/platform-letter`) is a script of the host's, installed outside this repository, that sets the state folder, sources `~/.local/bin/platform-letter-registry-env` and then runs the runtime's `scripts/platform-letter`;  the ZCode wrapper `~/.local/bin/zc-letter/platform-letter` does the same with `~/.local/bin/operator-registry-env` and finds the checkout itself.  Nothing in this client reads either env file:  that is deliberate, and the signing key never passes through this code from a file.  So every hook this client installs runs `<home>/.local/bin/platform-letter hook --platform <P>` (never a bare python path), and the retired `simple-chat letter ...` line, which sources nothing, re-runs itself once through that same wrapper with its arguments as this client reads them, when the process environment lacks the settings and the wrapper is on the host (`SIMPLE_TOOLS_LETTER_WRAPPED` marks the re-run).  With no wrapper, or with the settings already in the environment, it runs where it is.  On the server `~/.local/bin/platform-letter` is the fleet-cli managed wrapper, which sets nothing:  a server hook needs the settings in its own environment, as it does today.  This was run on the Mac against the real wrapper with an empty hook payload (nothing registers without a session id), and not on the server.
- **Open Claude chats keep their letter.**  A note the retired client wrote is read as it is and brought to the new shape the first time its chat's hook runs.
- **The gone report needs no deploy to work.**  The registry already serves `report-gone`.  The rule that a chat in use is kept (a named row its hook touched in the last 45 minutes stays open and is answered in `kept`) is in the registry service's own handler, so it holds from the service's next start on this code;  this page does not restart it.  A new client against the old handler works as before:  an answer with no `kept` is read as nothing kept.

**MiniMax is the one platform with a gap.**  Its installed hooks run the wrapper `~/.local/bin/mm-session-letter`, which looks for `scripts/mm_session_letter.py` in a checkout, finds none once that checkout is on this change, and exits 0.  From then until Mac step 3 a MiniMax chat's letter hook does nothing.  No registration is lost:  after step 3 an open chat takes its note from the retired client's own letter cache at its next turn end and re-attaches to the letter it holds.

## Mac

1. **Merge, and see the new runtime.**  The runtime sync brings `~/apps/lanes/_managed/fleet/simple-tools-runtime` to the merge within a few minutes.  `~/.local/bin/platform-letter` and `~/.local/bin/simple-chat` already lead into it, so `scripts/simple_tools/install.sh` is not needed on a Mac that has both.  Proof that the new code is live:  `platform-letter parent-ssh-gate; echo $?` prints `parent-ssh-gate: that command is not allowed on this key` and `126`.
2. **Claude.**  `platform-letter install --platform claude --check` answers exit 1 with every `current` false (the retired entries are there, and they are not this client's).  `platform-letter install --platform claude` rewrites SessionStart, UserPromptSubmit, Stop and SessionEnd in `~/.claude/settings.json` and names its backup (`settings.json.bak-letter-<UTC stamp>`) in the answer.  `--check` again answers exit 0 with every `current` true.  On this Mac the retired entries were read to have no Stop hook, so the first check also shows Stop as not installed;  this client hooks the turn end too.
3. **MiniMax.**  `platform-letter install --platform minimax --check` answers exit 1:  `current` is false for SessionStart and Stop, `retired.hooks` names `PreToolUse` and `retired.files` names the two wrappers.  `platform-letter install --platform minimax` replaces the two entries and takes out the retired `mm-session-letter hook-pre-tool-use` entry (its answer's `changed` is PreToolUse, SessionStart and Stop, and the backup is `hooks.json.bak-letter-<UTC stamp>`).  That entry refused a post that did not state the chat's letter, and this client has no such gate, on purpose.  `--check` still answers exit 1 until step 4, now with `retired.hooks` empty.
4. **ZCode.**  Its installed hook runs `~/.local/bin/zc-letter/platform-letter`, which keeps working after the merge:  it sources `~/.local/bin/operator-registry-env` and runs the checkout's `scripts/platform-letter`, which this change keeps (it was run from a clean environment against the new runtime and exited 0).  `platform-letter install --platform zcode --check` answers exit 1 and names the wrapper under `retired.files`;  `platform-letter install --platform zcode` rewrites the entries in `~/.zcode/cli/config.json` to the `~/.local/bin/platform-letter` command, and `--check` then has no `retired.hooks`.  Do this before Mac step 5, because moving the wrapper first leaves ZCode's hook with nothing to run.
5. **Move the retired wrappers aside.**  `~/.local/bin/mm-session-letter`, `~/.local/bin/mm-registry-env` and `~/.local/bin/zc-letter`.  Move them out of `~/.local/bin` and keep them until the change has settled, since going back needs them.  Keep `~/.local/bin/platform-letter-registry-env` and `~/.local/bin/operator-registry-env`:  the host's `platform-letter` wrapper and the wake delivery source them (this client never reads them).  Move `zc-letter` only after the ZCode step.  Proof:  `platform-letter install --platform minimax --check` answers exit 0, and neither it nor `platform-letter install --platform zcode --check` has a `retired` key.
6. **Take the archive step out of the sweep script.**  `~/.local/bin/operator-letter-sweep.sh` ends with a block of six lines, under the comment that begins `# Claude:  free the letters of Claude desktop chats the owner archived (AFC-694)`, that runs `"$REPO/simple-chat" letter sweep-archived --apply` and logs its answer.  The hooks send that report themselves now, at most once an hour for each platform and location, so the block goes.  The script as it was before the block is `~/.local/bin/operator-letter-sweep.sh.bak-20261112105322`:  `diff` the two, see that the block is the only difference, keep a copy of the live file for going back, and put the older one in its place.  Proof:  `/usr/bin/grep -c sweep-archived ~/.local/bin/operator-letter-sweep.sh` prints `0`.  Left in, the block does no harm:  `sweep-archived` is still read, as another name of `gone`.
7. **See the registry from a hook's side.**  `platform-letter registry show --platform smoke --location mac --session-id smoke-check-0001` answers `{"error": "this chat has no registration"}` with exit 5, which means the API is configured and answering.  `not_configured` means the hook's environment names no registry API.  The check a hook's own situation needs is from a clean environment, through the host's wrapper:  `env -i HOME=$HOME PATH=/usr/bin:/bin ~/.local/bin/platform-letter hook --platform claude < /dev/null` prints nothing and exits 0 when the wrapper is sound, since an empty payload names no chat and so registers nothing, and prints `platform-letter hook: no adapter for the platform` while the runtime under the wrapper is from before this change.  What tells configured from not is `env -i HOME=$HOME PATH=/usr/bin:/bin ~/.local/bin/platform-letter install --platform claude --check`, whose answer carries `"registry": {"configured": true}` when the settings reached the process, and `{"configured": false, "reason": "no URL: SIMPLE_TOOLS_OPERATOR_REGISTRY_URL is not set; knob: ..."}` (or `no key: ...`) when they did not:  variable and knob names only, never a value.  A chat's own context line says the same (`No Operator letter yet (no registry API URL is configured (...))`).  `platform-letter gone --platform claude` is a dry run:  it prints what the next report would name and sends nothing.  Do not run it with `--apply` by hand.
8. **The owner's step:  one line in the Mac's `authorized_keys`.**  Only for a server that runs Claude chats.  A server chat asks this Mac one question over ssh, which chat started it, and the key it asks with is allowed that question and nothing else.  The Mac's owner adds this line to `~/.ssh/authorized_keys` on the Mac, with the server account's public key in place of `<key-type> <public-key>`:

   ```
   restrict,command="$HOME/.local/bin/platform-letter parent-ssh-gate" <key-type> <public-key> letter-parent
   ```

   No installer writes that file.  Use a key of its own for this:  with the line in place the key can run nothing but the gate, so a key that also does other work on the Mac would lose it.  Proof, from the server, with DEST the name in the server account's ssh config that presents that key:  `ssh -o BatchMode=yes DEST true; echo $?` prints `parent-ssh-gate: that command is not allowed on this key` and `126`, and `ssh -o BatchMode=yes DEST platform-letter parent --platform claude --session-id smoke-check-0001; echo $?` prints nothing and `0`.

## Server

1. **The runtime, and the registry from a hook's side.**  `fleet-cli-git-update` brings the runtime to the merge.  The same two proofs as on the Mac:  `platform-letter parent-ssh-gate; echo $?` prints the refusal and `126`, and `platform-letter registry show --platform smoke --location server --session-id smoke-check-0001` answers `{"error": "this chat has no registration"}` with exit 5.  `not_configured` there means a hook on the server finds no registry API (`SIMPLE_TOOLS_OPERATOR_REGISTRY_URL` and its key in the environment, or `~/.local/bin/operator-registry-env`), and every chat would be titled `??`:  set that right before anything else.  The server reaches the registry itself;  nothing goes through the Mac any more.
2. **Claude.**  `platform-letter install --platform claude --location server --mac-ssh DEST`, then `platform-letter install --platform claude --location server --check` (exit 0, every `current` true).  The install's answer carries `mac_authorized_keys`, the line of Mac step 8, and `mac_note`, which says whose step it is.  Until this step the retired entries go on working, with the location and the destination the retired installer put in the `env` block of `~/.claude/settings.json`.
3. **The key line on the Mac** is Mac step 8, and it is the owner's.  Until it is there, or with the Mac unreachable, a server chat gets no answer within its 2 seconds and is placed as a main chat;  nothing else about its letter changes.
4. **Every other platform with hooks on the server.**  `platform-letter install --platform <name> --location server --check` for each one, and an install only where the check answers exit 1.

## What To Remove

- The three wrappers of Mac step 5, on each host that has them, once the change has settled.
- The archive block of Mac step 6.
- On the server, after its Claude install, `CLAUDE_LETTER_LOCATION` and `CLAUDE_LETTER_REMOTE` in the `env` block of `~/.claude/settings.json`:  nothing reads them once the retired entries are replaced.
- The retired MiniMax letter cache (`session-letters/<session id>.json` under MiniMax Code's hook data, for example `~/.minimax/hook-state/session-letters/`), once the chats that were open at the merge are closed.  It is read once, for a chat that has no note yet, and never written.
- If the server's key was accepted on the Mac without a forced command for the retired client's registry calls, that older `authorized_keys` line, which is the owner's to remove.

## Going Back

1. Revert the merge on main and let the runtime sync bring the retired clients back.
2. Put the hook entries back.  On the retired runtime a `platform-letter hook --platform claude` or `--platform minimax` entry does nothing and exits 0, because that runtime has no row for either platform.  Each install named its backup in its answer (`~/.claude/settings.json.bak-letter-<UTC stamp>`, `~/.minimax/hooks.json.bak-letter-<UTC stamp>`).  Put the backup in place when the file has not changed since;  otherwise put the retired entries back by hand from it.
3. Put the wrappers of Mac step 5 back in `~/.local/bin`.
4. Put the sweep script back as it was with the archive block, from the copy kept in Mac step 6:  on the retired code nothing else frees the letter of an archived Claude chat.
5. The `authorized_keys` line can stay.  The retired code never asks its question, and the key can do nothing else.
6. Not checked:  whether the retired clients read a note this client has rewritten.  A chat's registration is in the registry either way, under the same platform, host and session id, so a chat whose note is not taken registers again under the identity it already has.

## Checks

```bash
cd scripts && python3 -m unittest simple_tools.tests.test_platform_letter simple_tools.tests.test_platform_letter_claude simple_tools.tests.test_platform_letter_one_table -v
cd scripts && python3 -m unittest simple_tools.tests.test_listener_registry simple_tools.tests.test_cursor_cloud_letters -v
```

`RetiredHookCommandTests` runs the installed command line, `scripts/simple-chat letter hook`, as a process against a registry on loopback, with SessionStart, UserPromptSubmit, Stop and SessionEnd payloads.  `ParentTests` holds the gate's refusals, and `MiniMaxRetiredClient` the adoption of the retired cache.
