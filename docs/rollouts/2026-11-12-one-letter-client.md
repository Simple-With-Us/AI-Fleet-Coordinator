# [AFC-740](https://linear.app/simple-with-us/issue/AFC-740) One Letter Client:  Steps At Merge

> **Superseded Bootstrap Instructions.**  Follow [AFC-785's registry bootstrap and rollout contract](afc-785-letter-bootstrap.md) for current credentials, managed wrappers and activation checks.  This dated AFC-740 record preserves the earlier design; its env-helper provisioning and bash-wrapper examples are historical.  Each host's own narrow binding and native acceptance remain separate rollout gates.

One client, `platform-letter`, letters the chats of every platform from this change on, Claude Code and MiniMax Code included.  The two per-seat clients it replaces are gone from the checkout:  `scripts/simple_tools/claude_letter.py` (behind `simple-chat letter`) and `scripts/mm_session_letter.py` (behind `mm-session-letter`).

This page is the order of work on the Mac and on the server when the change merges, the check that proves each step, what to take away afterwards, and how to go back.  None of it was run against a real home, a real `authorized_keys` or the real registry in this change:  every command below was run against a throwaway home and an in-process registry, except the few that say they were run on the Mac, and each of those sent nothing to the registry.  The server was not reached at all.

## Read This First

- **The registry settings reach a hook through the host's wrapper, in shell, and never through this client's Python.**  A hook is launched with no profile, so its environment holds neither `SIMPLE_TOOLS_OPERATOR_REGISTRY_URL` nor its key, and a hook that runs with neither answers `not_configured` and no chat gets a letter.  The retired clients read the host's env script inside Python;  this client deliberately does not (a signing key is never read from a local file by our code).  What sets them instead is `<home>/.local/bin/platform-letter`, which every hook this client installs runs (never a bare python path):
  - **On the Mac** it is a script of the host's, installed outside this repository (a link to `~/.local/libexec/simple-tools-hooks/platform-letter`):  it sets the state folder, sources `~/.local/bin/platform-letter-registry-env` and runs the runtime's `scripts/platform-letter`.  `scripts/simple_tools/install.sh` no longer repoints it (it leaves an existing one as it is and says so);  `--force-platform-letter` overrides that, and would drop the settings from every Mac hook.
  - **On the server** it is the fleet-cli managed wrapper.  It used to set nothing, because the retired clients read the env script themselves.  `scripts/fleet-cli-release.py` now generates it as a bash wrapper that sources `~/.local/bin/platform-letter-registry-env` or, when that is absent, `~/.local/bin/operator-registry-env` (the file the server's other hooks read today), and `fleet-cli-git-update` rewrites an older managed `platform-letter` wrapper on its next run after the merge (a wrapper without the marker, and a link, are never touched).  Its text is under "The Managed Wrapper" below.
  - The retired `simple-chat letter ...` line (a Claude hook installed today), which sources nothing, re-runs itself once through `<home>/.local/bin/platform-letter` with its arguments as this client reads them, when its environment lacks the settings and that wrapper is on the host.  `SIMPLE_TOOLS_LETTER_WRAPPED` marks the re-run, so it happens once.  With no wrapper, or with the settings in place, it runs where it is.
  - ZCode's installed hook runs `~/.local/bin/zc-letter/platform-letter`, a host wrapper that sources `~/.local/bin/operator-registry-env` and runs the checkout's `scripts/platform-letter`;  that file stays in the checkout, so it keeps working after the merge.
- **Server Claude chats register through the Mac today and register directly after this.**  The retired Claude client on the server sent its registry calls over ssh to the Mac (`CLAUDE_LETTER_REMOTE`), so the server never needed the registry settings for Claude.  This client calls the registry API from the host the hook runs on.  So the settings must be provisioned on the server before the merge (Before The Merge, step 1), or every server Claude chat is titled `??`.
- **A server on the old code with a Mac on the new** (the two hosts update at different moments):  the old server client asks the Mac's `simple-chat letter registry register ... --host-session-id=...`, which the new Mac answers `{"error": "bad arguments"}` with exit 2.  The old client then retries without that flag, so the chat registers, but its sub-thread placement under its parent is lost for as long as that mix lasts.  To avoid it update the server first (its `fleet-cli-git-update` brings the runtime to main by itself), or accept the gap, which ends when both are on the new code.
- **The MiniMax gap starts when `~/Code/AI-Fleet-Coordinator` resets to main, not at the runtime sync.**  The installed wrapper `~/.local/bin/mm-session-letter` looks first for the managed runtime's `scripts/mm_session_letter.py` (not there on the Mac today) and then for the one in `~/Code/AI-Fleet-Coordinator`, which a daemon resets to main:  once that tree has this change the file is gone and the wrapper exits 0, so a MiniMax chat's letter hook does nothing until Mac step 3.  No registration is lost:  after step 3 an open chat takes its note from the retired client's own letter cache at its next turn end and re-attaches to the letter it holds.
- **A bundle-only host cannot run `platform-letter`.**  `scripts/platform-letter` is not in the release bundle's EXACT list (pre-existing:  its wrapper's own comment says so), so a host that holds only a pushed bundle and no git checkout has no script to run, and so no `platform-letter` and no `parent-ssh-gate`.  Every host runs from a git checkout (the server since Oct 19, 2026), the bundle path is paused, and adding the path also needs the doctor's `SHIPPED_EXACT` list and its pin test to move, so it is left as it is.
- **One oversized or unreadable Claude app record stops every gone report of that host.**  The archive reader skips a record it cannot read (too big, not openable, past its bounds) and then calls no chat archived, so no chat's letter is freed by a report until the record is gone or the 36 hour stale sweep ends the rows.  That fails safe, a letter is kept and never freed on a doubt, and it is not a bug to fix.

## Before The Merge

1. **Server:  provision the registry settings, and prove a clean environment finds them.**  The server's Claude hooks have not needed them.  `ls ~/.local/bin/platform-letter-registry-env ~/.local/bin/operator-registry-env` should name at least one (the second is the file the server's Codex, OpenCode and ZCode hooks read today).  If neither is there, the host's owner provisions one:  this change does not write it.  Proof, which prints a word and never a value:  `env -i HOME=$HOME PATH=/usr/bin:/bin bash -c '.  "$HOME/.local/bin/operator-registry-env" >/dev/null 2>&1; [ -n "$SIMPLE_TOOLS_OPERATOR_REGISTRY_URL" ] && [ -n "$SIMPLE_TOOLS_OPERATOR_REGISTRY_KEY" ] && echo set || echo MISSING'` prints `set` (use the name of the file that is there).
2. **Server first, if the mix matters.**  Let the server's `fleet-cli-git-update` take the merge before the Mac does, to avoid the sub-thread gap above.

## The Managed Wrapper

After the next `fleet-cli-git-update` (which runs after the merge reaches main) the server's `~/.local/bin/platform-letter` is exactly this, with `<home>` the server account's home folder:

```bash
#!/bin/bash
# fleet-cli managed wrapper v1
# The registry settings of a session-letter hook come from the host's env script, sourced here in shell.
for f in "$HOME/.local/bin/platform-letter-registry-env" "$HOME/.local/bin/operator-registry-env"; do
  if [ -f "$f" ]; then
    if [ "$( . "$f" >/dev/null 2>&1 </dev/null; echo ok )" = ok ]; then
      . "$f" >/dev/null 2>&1 </dev/null
      export SIMPLE_TOOLS_OPERATOR_REGISTRY_URL SIMPLE_TOOLS_OPERATOR_REGISTRY_PRINCIPAL SIMPLE_TOOLS_OPERATOR_REGISTRY_KEY
    fi
    break
  fi
done
exec /usr/bin/python3 -I -B <home>/.local/share/fleet-cli/current/scripts/platform-letter "$@"
```

The first env script that is a file is the one used.  It is run once in a subshell with its output thrown away and is sourced into the wrapper only when that run reached its end, so a script that exits cannot stop a hook;  one that fails or does not parse is sourced as far as bash goes and the hook runs all the same.  Nothing it prints is shown, its status is not the wrapper's, and the three names it may set are exported whether or not it exported them.  The wrapper `exec`s, so the hook's standard input and arguments reach the script as they came.  A wrapper the host wrote itself (no marker line) is never rewritten.

## Mac

1. **Merge, and see the new runtime.**  The runtime sync brings `~/apps/lanes/_managed/fleet/simple-tools-runtime` to the merge within a few minutes.  `~/.local/bin/platform-letter` and `~/.local/bin/simple-chat` already lead into it, so `scripts/simple_tools/install.sh` is not needed on a Mac that has both, and it leaves an existing `platform-letter` as it is.  Proof that the new code is live:  `platform-letter parent-ssh-gate; echo $?` prints `parent-ssh-gate: that command is not allowed on this key` and `126`.
2. **See the registry from a hook's side.**  From a clean environment, through the host's wrapper:  `env -i HOME=$HOME PATH=/usr/bin:/bin ~/.local/bin/platform-letter install --platform claude --check`.  Its answer carries `"registry": {"configured": true}` when the settings reached the process, and `{"configured": false, "reason": "no URL: SIMPLE_TOOLS_OPERATOR_REGISTRY_URL is not set; knob: ..."}` (or `no key: ...`) when they did not:  variable and knob names only, never a value.  A chat's own context line says the same (`No Operator letter yet (no registry API URL is configured (...))`).  The smaller form `env -i HOME=$HOME PATH=/usr/bin:/bin ~/.local/bin/platform-letter hook --platform claude < /dev/null` prints nothing and exits 0 when the wrapper is sound, since an empty payload names no chat and so registers nothing, and prints `platform-letter hook: no adapter for the platform` while the runtime under the wrapper is from before this change;  it cannot tell configured from not, which the `install --check` form does.  `platform-letter registry show --platform smoke --location mac --session-id smoke-check-0001` answers `{"error": "this chat has no registration"}` with exit 5 when the API is configured and answering, and `not_configured` otherwise.  Do this before the installs below.
3. **Claude.**  `platform-letter install --platform claude --check` answers exit 1 with every `current` false (the retired entries are there, and they are not this client's).  `platform-letter install --platform claude` rewrites SessionStart, UserPromptSubmit, Stop and SessionEnd in `~/.claude/settings.json` and names its backup (`settings.json.bak-letter-<UTC stamp>`) in the answer.  `--check` again answers exit 0 with every `current` true.  A check exits 0 only when every hook is installed and current and no retired hook or wrapper is left.  On this Mac the retired entries were read to have no Stop hook, so the first check also shows Stop as not installed;  this client hooks the turn end too.
4. **MiniMax.**  `platform-letter install --platform minimax --check` answers exit 1:  `current` is false for SessionStart and Stop, `retired.hooks` names `PreToolUse` and `retired.files` names the two wrappers.  `platform-letter install --platform minimax` replaces the two entries and takes out the retired `mm-session-letter hook-pre-tool-use` entry (its answer's `changed` is PreToolUse, SessionStart and Stop, and the backup is `hooks.json.bak-letter-<UTC stamp>`).  That entry refused a post that did not state the chat's letter, and this client has no such gate, on purpose.  `--check` still answers exit 1 until step 6, now with `retired.hooks` empty.  An open MiniMax chat takes its note from the retired client's letter cache at its next turn end:  the cache is in `~/.minimax/v2/hook-data/user/session-letters/` (the live one) and in `~/.minimax/hook-state/session-letters/` (the layout before it, which holds old files), and the file written last is the one adopted, never both.
5. **ZCode, last of the installs.**  Its installed hook runs `~/.local/bin/zc-letter/platform-letter`, which keeps working after the merge (see Read This First).  `platform-letter install --platform zcode --check` answers exit 1 and names the wrapper under `retired.files`;  `platform-letter install --platform zcode` rewrites the entries in `~/.zcode/cli/config.json` to the `~/.local/bin/platform-letter` command, and `--check` then has no `retired.hooks`.  Do this before the next step, because moving the wrapper first leaves ZCode's hook with nothing to run.
6. **Move the retired wrappers aside.**  `~/.local/bin/mm-session-letter`, `~/.local/bin/mm-registry-env` and `~/.local/bin/zc-letter`.  Move them out of `~/.local/bin` and keep them until the change has settled, since going back needs them.  Keep `~/.local/bin/platform-letter-registry-env` and `~/.local/bin/operator-registry-env`:  the host's `platform-letter` wrapper and the wake delivery source them (this client never reads them).  Move `zc-letter` only after the ZCode step.  Proof:  `platform-letter install --platform minimax --check` answers exit 0, and neither it nor `platform-letter install --platform zcode --check` has a `retired` key.
7. **Take the archive step out of the sweep script.**  `~/.local/bin/operator-letter-sweep.sh` ends with a block of six lines, under the comment that begins `# Claude:  free the letters of Claude desktop chats the owner archived (AFC-694)`, that runs `"$REPO/simple-chat" letter sweep-archived --apply` and logs its answer.  The hooks send that report themselves now, at most once an hour for each platform and location, so the block goes.  The script as it was before the block is `~/.local/bin/operator-letter-sweep.sh.bak-20261112105322`:  `diff` the two, see that the block is the only difference, keep a copy of the live file for going back, and put the older one in its place.  Proof:  `/usr/bin/grep -c sweep-archived ~/.local/bin/operator-letter-sweep.sh` prints `0`.  Left in, the block does no harm:  `sweep-archived` is still read, as another name of `gone`.  `platform-letter gone --platform claude` is a dry run:  it prints what the next report would name and sends nothing.  Do not run it with `--apply` by hand.
8. **The owner's step:  one line in the Mac's `authorized_keys`.**  Only for a server that runs Claude chats.  A server chat asks this Mac one question over ssh, which chat started it, and the key it asks with is allowed that question and nothing else.  The Mac's owner adds a line like this one to `~/.ssh/authorized_keys` on the Mac:

   ```
   restrict,from="<server-ip>",command="<abs path of scripts/platform-letter> parent-ssh-gate" <key-type> <public-key> letter-parent
   ```

   `<server-ip>` is the server's address, so the key works from nowhere else.  The command is the checkout's own `scripts/platform-letter` by absolute path, not the host's `platform-letter` wrapper, so the key's process never holds the registry settings.  On the Mac, `platform-letter parent-key-line --from <server-ip>` prints the line with the Mac's own path, and the server's `install --mac-ssh` prints the same line with the path of the checkout it ran from, which is the server's:  use the Mac's.  The key's own public half goes in place of `<key-type> <public-key>`.  No installer writes that file.

   Use a key of its own, and name it for the server by an alias.  The Mac already has an unrestricted line for another key, and sshd takes the first line that matches the key presented:  if DEST presents that other key the gate line never applies and the server holds a shell on the Mac.  So DEST is a `Host` alias in the server account's ssh config with its own `IdentityFile` and `IdentitiesOnly yes` (the client also sends `IdentitiesOnly=yes`, `ControlPath=none` and `ControlMaster=no`, so no agent key and no shared connection can stand in).  Proof, from the server:  `ssh -o BatchMode=yes DEST true; echo $?` must print `parent-ssh-gate: that command is not allowed on this key` and `126`.  If it prints `0` the wrong key is being offered, and the gate is not in the way;  stop and fix the alias.  Then `ssh -o BatchMode=yes DEST platform-letter parent --platform claude --session-id smoke-check-0001; echo $?` prints nothing and `0`.  A key with this line can run nothing but the gate, so a key that also does other work on the Mac would lose it.

## Server

1. **The runtime, and the registry from a hook's side.**  `fleet-cli-git-update` brings the runtime to the merge and rewrites the managed `platform-letter` wrapper (Read This First).  Proof, from a clean environment through the wrapper, as a hook runs:  `env -i HOME=$HOME PATH=/usr/bin:/bin ~/.local/bin/platform-letter install --platform claude --location server --check` carries `"registry": {"configured": true}`.  A `configured: false` there means the settings did not reach the process:  every chat would be titled `??`, so set that right before anything else (Before The Merge, step 1).  The same two proofs as on the Mac:  `env -i HOME=$HOME PATH=/usr/bin:/bin ~/.local/bin/platform-letter parent-ssh-gate; echo $?` prints the refusal and `126`, and `... platform-letter registry show --platform smoke --location server --session-id smoke-check-0001` answers `{"error": "this chat has no registration"}` with exit 5.  An interactive shell is not a hook's environment, which is why the proofs name `env -i`.  The server reaches the registry itself;  nothing goes through the Mac any more.
2. **Claude.**  `platform-letter install --platform claude --location server --mac-ssh DEST`, then `platform-letter install --platform claude --location server --check` (exit 0, every `current` true).  The install's answer carries `mac_authorized_keys`, the line of Mac step 8, and `mac_note`, which says whose step it is.  Until this step the retired entries go on working:  their hook line re-runs through the wrapper with the location and the destination the retired installer put in the `env` block of `~/.claude/settings.json`.
3. **The key line on the Mac** is Mac step 8, and it is the owner's.  Until it is there, or with the Mac unreachable, a server chat gets no answer within its 2 seconds and is placed as a main chat;  nothing else about its letter changes.
4. **Every other platform with hooks on the server.**  `platform-letter install --platform <name> --location server --check` for each one, and an install only where the check answers exit 1.
5. **ZCode, last.**  `platform-letter install --platform zcode --location server` replaces a working `zc-letter` entry with the `<home>/.local/bin/platform-letter` command, which now sources the env script like `zc-letter` did, so the hook goes on registering (a server-shaped home with the managed wrapper and a `zc-letter` wrapper was tested to).  Do it after the checks of steps 1 and 2 have shown the settings reach a clean environment.

## What To Remove

- The three wrappers of Mac step 6, on each host that has them, once the change has settled.
- The archive block of Mac step 7.
- On the server, after its Claude install, `CLAUDE_LETTER_LOCATION` and `CLAUDE_LETTER_REMOTE` in the `env` block of `~/.claude/settings.json`:  nothing reads them once the retired entries are replaced.
- The retired MiniMax letter caches (`session-letters/<session id>.json` under `~/.minimax/v2/hook-data/user/` and `~/.minimax/hook-state/`), once the chats that were open at the merge are closed.  They are read once, for a chat that has no note yet, and never written.
- If the server's key was accepted on the Mac without a forced command for the retired client's registry calls, that older `authorized_keys` line, which is the owner's to remove.

## Going Back

1. Revert the merge on main and let the runtime sync bring the retired clients back.  On the server `fleet-cli-git-update` writes missing wrappers and rewrites the managed `platform-letter` one;  after a revert the older checkout does not know how to rewrite it, so the bash wrapper stays, and it still runs the checkout's `scripts/platform-letter`.
2. Put the hook entries back.  On the retired runtime a `platform-letter hook --platform claude` or `--platform minimax` entry does nothing and exits 0, because that runtime has no row for either platform.  Each install named its backup in its answer (`~/.claude/settings.json.bak-letter-<UTC stamp>`, `~/.minimax/hooks.json.bak-letter-<UTC stamp>`).  Put the backup in place when the file has not changed since;  otherwise put the retired entries back by hand from it.
3. Put the wrappers of Mac step 6 back in `~/.local/bin`.
4. Put the sweep script back as it was with the archive block, from the copy kept in Mac step 7:  on the retired code nothing else frees the letter of an archived Claude chat.
5. Leave the `authorized_keys` line in place:  the retired code never asks its question, and the key can run nothing but the gate.
6. Not checked:  whether the retired clients read a note this client has rewritten.  A chat's registration is in the registry either way, under the same platform, host and session id, so a chat whose note is not taken registers again under the identity it already has.

`RetiredHookCommandTests` runs the installed command line, `scripts/simple-chat letter hook`, as a process against a registry on loopback, with SessionStart, UserPromptSubmit, Stop and SessionEnd payloads.  `HostWrapperTests` holds the wrapper path every install writes, the retired command line's single re-run and the reason a missing setting names.  `RegistryEnvWrapperTests` runs the generated server wrapper as a process against fake env scripts (one, the other, neither, a failing and a garbled one).  `ParentTests` holds the gate's refusals, and `MiniMaxRetiredClient` the adoption of the retired cache.
