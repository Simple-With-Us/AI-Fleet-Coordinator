# Compliance Inventory: What AFC, Fleet-OPS And The Fleet Already Enforce

**Issue:** AFC-396.  **Status:** first full pass, Sat, Oct 24, 2026.  **Owner of this document:** OPENCODE.

## What This Document Is

This is the inventory JET asked for on Oct 21, 2026: a single table of every control the fleet already enforces today, whether it is a script, a policy document, a guard, a watcher, a cron row, a launchd job or a review rule.  The purpose is to list what exists **before** the Muster compliance registry absorbs it, so the registry does not silently overwrite a control the fleet depends on, and so the owner can see what would be retired versus what would become a checked rule.

Nothing here changes behaviour.  Every row describes what already runs.

### What "Rule", "Retire" And "Keep Outside Muster" Mean

| Disposition | Meaning |
|---|---|
| **rule** | The control already enforces something checkable and should become (or already is) a row in the Muster compliance registry, checked by a collector.  The follow-up column names the proposed rule id and the collector that would run it. |
| **retire** | The control is superseded, dead, or its job is done.  It should be removed, and the follow-up column names what replaces it. |
| **keep outside Muster** | The control is real and stays, but it is not a compliance rule.  The reason column says why: it is a service, a product surface, a vendor job, a document, or a per-app concern that belongs to an app repo rather than the fleet registry. |
