# Finder Infisical Reader Binding

This source remains held until current shared dependencies, native CI/review, own-reader grant and custody, actual Finder acceptance and explicit owner release are verified.  No live grant, registry row, Keychain account, installed replacement or acceptance is claimed here.

Both production Controls readers use `FleetSecrets.managed()`.  Its default initializer has the same managed behavior; there is no raw token-binding initializer or unselected-account fallback.  The declaration is exactly `<home>/.config/infisical/muster.json`, selected with `--consumer-binding` and `--consumer muster-data-reader` on each `get`, `names` and `doctor` call.  The local nonsecret knob catalog needs no binding.

The authoritative schema is [Declared Consumer Reader](../../docs/protocols/declared-consumer-reader.md).  Its exact fields are `schemaVersion`, `consumer`, `project`, `projectId`, `environment`, `secretPath`, `permissions`, `expiresAt`, `tokenName`, `tokenId` and `storage`.  The declaration names `muster-data-reader`, `fleet-ops`, prod, `secretPath` equal to `/`, permission `["read"]`, and the actual approved registry record's finite future expiry and identifiers.  `storage` has exactly kind `mac-login-keychain`, service `infisical-service-token` and account equal to that record's `tokenName`.  Inline values, inferred accounts and unknown or duplicate fields are refused.

The declaration's immediate directory belongs to the current user with mode `0700`; the regular file has the same owner, mode `0600`, one link and at most 16 KiB.  The shared reader walks held descriptors without following symlink components and rechecks captured directory/file identity.  The native source does not create this declaration or change its permissions.

The shared custody primitive reads only the exact named service/account from the caller home's `Library/Keychains/login.keychain-db`, passed explicitly to `security`.  Its five-second maximum, bounded capture and discarded stderr apply before the named worker's separate 30-second budget.  There is no keychain-search-list, other-account, file, environment-token or session fallback.  The reader verifies exact live token ID/name, resolved project, prod root read permission and the same finite expiry before value access.

Native Python is `/usr/bin/python3 -I` with the absolute existing `scripts/infisical-scoped.py` entry in the located reviewed engine.  The interpreter override exists only as an explicit source-test seam; ordinary engine interpreter environment overrides do not select the production reader interpreter.  The subprocess receives only `HOME` and the system `PATH`, excluding ambient tokens, API overrides and folder markers, including empty markers.  Project resolution continues through existing approved metadata and must match the declaration.

Names and doctor are metadata-only and perform no value read.  Doctor returns its fixed JSON contract without `--json` or `--path`; arbitrary fields and diagnostic strings are dropped by the native display.  The 45-second native runner timeout preserves room for the selected named worker and separate store budgets; its existing termination grace is separate, and it is not an assertion of the historical 15-second total deadline.

The shared AFC-867 source and normal reviewed release payload must precede activation.  The authorized provisioner must establish the actual own registry record, finite exact grant, protected declaration and exact login-Keychain item, then demonstrate scoped `get`, metadata-only `names` and masked `doctor` in the real Finder context.  Synthetic source fixtures do not satisfy those gates.  The existing owner hold also covers automatic Sparkle publication; no source result releases it.
