# Finder Infisical Reader Binding

This source remains draft until its shared dependencies, hosted native tests, own-reader inventory and real Finder acceptance are verified, and the authorized setter clears the existing release hold.  No registry row, keychain account, grant, installed app or live acceptance is claimed here.

Both production Controls readers use `FleetSecrets.managed()`.  The factory selects the nonsecret declaration `~/.config/infisical/muster.json`; construction reads no credential or store.  The existing initializer remains an explicit-binding test seam and does not opt into keychain access.  The declarations-only knob catalog needs no binding.

The one shared command accepts `--consumer-binding <absolute declaration path>` only for `get`, `names` and an explicitly selected `doctor --project fleet-ops --path /`.  The declaration must name consumer `muster-data-reader`, project `fleet-ops`, prod, exactly `/`, read-only permission and a finite future expiry.  It contains the approved registry record's `tokenName`, `tokenId` and `projectId`, plus `schemaVersion` equal to 1.  Its `storage` object has kind `mac-login-keychain`, service `infisical-service-token`, and account equal to that exact registry token name.  No account is inferred or supplied as a default.

The directory must belong to the current user with mode `0700`; the regular declaration file must have the same owner, mode `0600`, one link and at most 16 KiB.  Symlink components, duplicate or unknown fields, inline values, unsafe metadata and unsupported routes fail before keychain or provider access.  Existing Infisical authentication and API override bindings conflict with this selection, including empty markers.  A metadata document is a selection, not proof of a live grant.

The generic shared bootstrap reads only the declared keychain service/account with bounded capture and a five-second maximum.  Captured output is never relayed; failure never tries another account, file, session or token.  The shared Infisical client then verifies the live token ID/name, exact project/prod/root/read grant and finite expiry before any value access.  The command builds a private minimal environment; Swift receives neither the bootstrap token nor another consumer's binding.

The selected route has one 15-second total budget inside Muster's 20-second process limit.  Its doctor skips the unrelated optional installed-CLI version probe and reports that probe as not requested; it retains the already-approved root value-validation/counts behavior, with masked output.  Ordinary unselected doctor behavior stays compatible.  Names remain metadata-only and get requests only named values.

Dependencies are the canonical reader in #2167, shared command in #2176, shared bootstrap/release packaging in #2166, and held native source in #2184.  This source adds no REST client, credential transport, writer purpose/store, token minting or host activation.  Before activation, the authorized provisioner must use the approved GUI/API inventory route to establish the actual own registry record and keychain item, verify scope in both directions and finite expiry, then demonstrate names, a safely captured named read and masked doctor from the owner's real Finder context without shell-token injection.  Source fixtures cannot satisfy that rollout gate.
